# 기능과 문서와 버그 변경 절차

## 시작

변경 목적, 해당 REQ ID, 영향을 받는 상태·계약을 확인합니다. 미확정 수치를 선택하거나 여러 폴더를 바꾸면 작업 계획과 DEC 항목을 먼저 기록합니다. 간단한 오탈자 수정은 별도 계획 없이 처리합니다.

## 변경

- 기능: PRD 범위 → 화면·상태 → 분석·데이터 계약 → 구현 → fixture·인수 조건 순서로 연결합니다.
- 버그: 재현 입력·기대 결과·실제 결과를 남기고 어느 계약이 깨졌는지 확인합니다. 해당 경계에 필요한 회귀 검증을 추가합니다.
- 문서: 원문과 설계 제안을 구분하고 상대 링크·색인·manifest·추적표를 갱신합니다.
- 정책: 수치·알고리즘 변경은 새 policy_id와 이유를 기록합니다. 기존 세션의 기준을 덮어쓰지 않습니다.

## 완료

하네스 검사, 변경 경계의 제품 검증, 개인정보 영향 확인을 수행합니다. 수행하지 못한 검증과 이유를 구체적으로 남깁니다. 제품 시나리오 passed는 증거를 연결한 뒤에만 설정합니다. 리뷰는 [검토 기준](review.md)을 따릅니다.

변경 결과에는 무엇이 바뀌었고 왜 필요한지, 검증한 범위, 남은 미확정 항목을 기록합니다. 커밋·푸시·배포는 사용자가 요청한 범위에 따라 수행합니다.
